## 第七十二轮：返回开始界面不再重播进度条（下午）
- 现象：游戏内点返回 → loadScene('Load') 整场景重建，LoadScene 的进度条动画白跑 ~2.1s
  （update 里 shown+=dt*0.55 从 3% 爬 99.5% 要 1.75s + onReady 淡出 0.35s；资源其实早常驻就绪）。
- **改了什么**：Res.ts 加模块级 `bootFlags = { loaded: false }`（loadAll finish 置位 / release 清位）；
  LoadScene.onLoad 判 `bootFlags.loaded` → `skipLoading()`（按掉 LoadingRoot + 后台补 loadAll/preload + 立即 showPage(StartPage)）。
- **★关键教训（无头验收抓出来的）**：第一版用「LoadScene 类静态 booted」做判据，被验收当场否决——
  **构建包启动场景直接是 Game**（profiles/v2/packages/builder.json startScene=Game.scene.uuid），
  Load 的 onLoad 在首次返回前从没跑过 → 第一次返回仍走完整进度条（实测 2421ms vs 快路径 259ms）。
  「资源加载过没有」必须由资源模块自己说了算，且必须用**模块级标记**（Res 实例随场景销毁，
  首次返回时 Load 场景反序列化出的是全新 Res 副本，实例字段全空）。
- 验收数据（_q71b_back2.tpl）：第1次返回 344ms（原 2421ms）、第2次 244ms，LoadingRoot 恒 hidden，标题页贴图正常。
- skipLoading 里**必须补跑** res.loadAll()：新 Res 副本 frames/clips 是空字典，StartPage 靠 prefab
  序列化引用没事，但再进 Game 后瓶子/Fx 走 Res.sf() 会满屏白块。loadAll 缓存命中瞬时完成。
- 验收模板 `_workbench/_tpl/_q71_back.tpl`（v1）/ `_q71b_back2.tpl`（v2），耗时用 rAF 轮询打点测。
