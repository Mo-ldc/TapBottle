## 第四十九轮：修复「点返回按钮报错 Cannot read properties of null (reading 'length')」
**根因（引擎 AttachPersist 与常驻节点副本冲突）**：`Load.scene` 文件里序列化了 `Res` 节点，
运行时它被 `addPersistRootNode` 常驻。点返回 → `loadScene('Load')` 二次进 Load 时，引擎
`runSceneImmediate` 的 **AttachPersist 分支**发现新场景反序列化出 **uuid 相同的 Res 副本**
→ `existNode._destroyImmediate()` 销毁新副本、换插首次启动的常驻老节点；
而 `LoadScene` 的 `@property resNode` 仍指向已销毁副本 → `getComponent(Res)` 读 `null._components` 报错。
**只有第二次进 Load 才发生**；build 包不炸是因为构建运行时 SceneAsset 缓存复用同一 Scene 实例、
走的是 else 重新挂载分支（不销毁副本）——复现/验证只在预览页 7456。
**复现手法**：`_cdp_url.py` 打预览页 → StartPage 点开始 → Game 里点 btn_back（jsclick 节点世界坐标换算）
→ CDP 捕获 `Runtime.exceptionThrown` 拿到堆栈：`LoadScene.onLoad → getComponent → Node._findComponent(comps.length)`。
⚠️ `getComponent('GameRoot')` 按类名取用户脚本组件会拿 null（editor 目标 cid 不同），直接调用组件方法验证不可行，要用真实点击。
**修复（LoadScene.ts onLoad）**：① `resNode.isValid === false` 时按 `scene.getChildByUuid(resNode.uuid)` 找回
常驻老节点（两份 uuid 相同）；② `addPersistRootNode` 前加 `!director.isPersistRootNode()` 防重复登记；
③ 取 Res 时加 `isValid` 守卫、兜底 `Res.I`（常驻老节点 ready=true，loadAll 幂等直接回调）。
**验证**：typecheck 0 错 → 构建 Finished → 预览页 Load→Game→点返回：scene=Load、**0 异常**、
