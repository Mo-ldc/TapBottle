## 第四轮：用户「解锁光标后，图片不在上层、被挡住了、没出现在手指点击处」

先做**不依赖输入的探针**（`_testcur.tpl`）排除坐标映射嫌疑：
- `ut.convertToNodeSpaceAR(field.node.getWorldPosition())` = `(0,0)` → 映射本身是对的；
  本工程 UI 世界原点 = 可见设计区左下角，所以 `getUILocation()` 与 `convertToNodeSpaceAR` 的入参**是同一个空间**，不需要加减半屏。
- 探针同时暴露真正的问题：`kids=[cursor,shadows,bottles,label]`、`cursor sib=0` —— 光标容器**整块**被压到了影子层/瓶子层之下。
- `f.pointer` 只在 `input TOUCH_MOVE` 里更新 → 「只点不拖」时永远停在初值。

三个成因与修法：
1. **层级**：光标拆成两个独立节点 —— `cursorRing`（范围圈，`setSiblingIndex(0)` 当地面贴片，压在影子/瓶子之下）+ `cursorPin`（手指，追加到子节点末尾 = 最上层）。原来共用一个容器、整容器 sib=0，手指跟着一起沉底。
2. **跟随**：`TOUCH_START` 也要取坐标，而且**桌面浏览器用鼠标时按下派发的是 `MOUSE_DOWN` 而不是 `TOUCH_START`**（实测：只点不拖时 pointer 纹丝不动，拖动才动 → 拖动的更新其实来自我新加的 `MOUSE_MOVE`）。
   现在四路都接：节点级 `TOUCH_START/MOVE` + `input TOUCH_START/MOVE` + `input MOUSE_DOWN/MOUSE_MOVE`，统一走 `aim(uiX, uiY)`。
   注意：`Bottle.enableTouch` 在 TOUCH_START 里 `propagationStopped = true`，所以**点在瓶子上时节点级 TOUCH_START 不会冒泡到 field**，必须靠 `input` 级的 MOUSE_DOWN / TOUCH_START 兜住。
3. **指尖精准落点**：用 PIL 量 `env/cursor.png`（73×78）最上面 6 行不透明像素的重心 → 指尖在贴图中心 `(−0.048, +0.487)` 比例处；于是贴图中心要放 `pointer + (−TIP_RX*W, −TIP_RY*H)` ≈ `(+2.7, −29.2)`。原来摆在 `(0,-6)`，指尖比触摸点高了约 23px。
   另：给手指加了一层右下偏移 3~4px 的黑影（`#101010`、opacity 95）—— 瓶子也是粗黑描边，手指直接叠上去会糊成一团。
4. 首次可用时把 `pointer` 摆到 `PLAY_AREA` 中心（`pointerSeeded`），否则停在节点原点看着像「没出现在该在的地方」。

验收（`_cdp.py` 新增 `drag:` / `jsdrag:` 指令，用真实 mousePressed→mouseMoved×8→mouseReleased 驱动）：
`A 初值 pointer=(30,65)+环激活+ring sib=0/pin sib=4` → `B 单击后 expect=(-70.4,78.8) vs pointer=(-71.1,79.1)` → `C 拖动后 expect=(24.8,-92.1) vs pointer=(24.3,-91.4)` → `D 关掉 p_cursor 后 ring/pin 都 act=false`。p16 与 tall 两比例一致，误差 <1px。

★ **易错**：`cursorPin` 的投影必须做成它自己的**子节点**且排在手指前面 —— Cocos UI 渲染是深度优先，同一节点自己的 Sprite **先画**、子节点后画；把投影做成 pin 自身 Sprite 的兄弟会盖在手指上（实测整只手被染成灰色）。

### 附带修掉：一次点击翻两只瓶子（`_testdbl.tpl` 实测 flips 0→2→4）

- 现象：点一只瓶子，`G.data.stats.flips` 每次 +2。
- 成因：`Bottle.enableTouch` 在 **TOUCH_START** 翻那只瓶子并 `propagationStopped = true`；
  而场地的「空白处点击 → 翻转随机瓶子」挂在 **TOUCH_END**（没有那层拦截），事件照样冒泡上来 → 再随机翻一只。
- 修法：场地那条改成挂 **TOUCH_START** —— 点在瓶子上时事件已被 `propagationStopped` 截断，走不进来；
  只有真正的空白处按下才会触发。改完实测 `flips 0→1→2`（每次点击正好一只），货币增量也对上了。
- 顺带好处：响应从「抬起手」提前到「按下」，手感更跟手。

## 第六轮：用户「金币文本和效果文本还在背景的后面」

一句话定位：**`fxLayer`（所有飘字的老家）在世界层的兄弟序是 0，一直压在桌面之下**。

证据（探针 `_testfxz.tpl`）：
`worldLayer.children = fxLayer#0, table#1, bottles#2, hands#3, caps#4` → `fxLayer sib=0`。
我在桌子正中间 spawn 了 `+$5` / `扣盖` / `MISS` 三个飘字，截图里**一个都看不到**（全部被桌面挡住）。

成因（典型的「建得早 = 画得早」错位）：
`fxLayer` 是在 `GameRoot.onLoad()` 里挂到 `worldLayer` 的（挂世界层是为了和世界坐标一起缩放/平移对齐），
而 `table / bottles / hands / caps` 是后面 `buildWorld()` 才建的 —— 后加的排在后面（画在上面），
于是后建的桌面把先建的特效层整个盖住。

修法：`buildWorld()` 末尾 `this.fxLayer.setSiblingIndex(this.worldLayer.children.length - 1);`
（仍在 `shakeHolder` 内，坐标一致性不受影响）

验收：
- 修后 `worldLayer.children = table#0, bottles#1, hands#2, caps#3, fxLayer#4`，三个测试飘字全部浮在桌面上；
- 真实翻转抓帧：`扣盖 $5`（金色）明确压在桌面木纹之上（`_shots/crop/fxw_hit_2.png`）；
- p16 / 9:20 两比例一致。
- 附带确认：飘字时长 0.85s、`fadeStart=0.42` → **只有落地后 0.36s 内是满不透明**，之后开始淡出，
  所以抓帧要卡在落地后 0.2~0.4s（抓晚了会以为「没渲染」，我第一轮就被这个骗了）。
