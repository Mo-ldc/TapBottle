## 第五轮：把「三态落地」做成看得见的姿态（用户明确要求）

用户澄清：瓶子落地有 **3 种状态**，必须和代码里的三个 outcome 一一对应——
1. **平放**（随机倒向左侧或右侧）→ **不得钱** = `fail`
2. **瓶口朝上**（正立）→ 得基础金币 = `ok`
3. **瓶口朝下**（倒扣在瓶口上，即原版的「扣盖」）→ **得钱最多** = `crit`

此前三种 outcome 的动画**都是站着的**，只靠弹跳幅度区分，肉眼看不出来。`Bottle.ts` 重写为「姿态驱动」：

- 新增 `Pose { angle, dx, dy }` + `Bottle.poseOf(outcome)`：
  `crit → {180°, 0, bottleH*0.32}`（倒立要整体抬高，否则瓶口插进桌面）、
  `fail → {±93°, 0, -8}`（随机左右躺平）、`ok → {0°, 0, 0}`。
- 新增 `restDx / restDy`：记录静止姿态相对格子中心的偏移，`moveHome()`/`applyRest()` 统一走它，
  否则 `BottleField.layout()` 一排版就会把躺着的瓶子拽回格子中心。
- 旋转改为**从当前角度起转**：`endAngle = start + spins + angDelta(start, pose.angle)`
  （`angDelta` 取最短角差），所以躺着的瓶子被再翻时是「先翻身再落地」，不会瞬移。
- `fail` 不再自动扶正：躺姿保持，符合原版（原版截图里也满地躺瓶）。
- `forceFlip`（可乐冲击波）与 `executeLand`（武士处决）也统一落到**瓶口朝下**的最优姿态。
- 扣盖时瓶盖从**瓶子下沿**喷出（`p.y - bottleH*0.34`），因为倒立后瓶口在下面。
- 另外在 `GameRoot.onLoad` 里 `profiler.hideStats()`，关掉 debug 构建默认弹出的性能面板（截图/录屏才干净）。

**验收**（`_test5.txt`，monkey-patch `G.rollOutcome` 强制三态各跑一遍）：
`POSE-OK angles=0,0,0,0,0,0` / `POSE-CRIT angles=…,180,…,180` 且 y 从 -135 抬到 -84 /
`POSE-FAIL angles=93,-93,93,…,-93,-93` 且 x 相对格子发生 ±42 横移。三态在截图里肉眼可辨。

> ⚠️ **上方那组角度是错的，已被第六轮修正**：`bottle/body_*.png` 贴图本身画的是**瓶口朝下**（原版 water-bottle-flip 的立瓶姿态），
> 所以角度 0° 实际是倒立。正确映射见下面「姿态反向」一节。

## 第六轮：随机落点 / 可堆叠 / 音效 / 面向大量瓶盖的性能优化

用户四点需求：① 中间画布是瓶子翻转后能跳到的**随机**位置集合，瓶子可**堆叠**；② 加**玩家点击音效**；③ 加**瓶子落地音效**；④ 加**金币飘字**；
⑤ （性能）**字体放同一层级方便合批**，且「后续产生的瓶盖可能比较多」，一定要最大化优化。

### A. 瓶子在桌面自由活动（`PLAY_AREA`）
- 新增 `PLAY_AREA = { x0 -105, x1 165, y0 -155, y1 285 }`（已按瓶身外扩留边：站立上下 ~55/105、平躺横向可伸 ~105）。
- **删掉原来的 4×6 网格排版**，改成 `BottleField.pickSpot()`：随机取 6 个候选点，选「离其他瓶子最远」的那个 ——
  允许堆叠但不会完全重合。新瓶子随机撒点；**每次落地也重新取点**（`Bottle.flip(outcome, speed, silent, target)` 新增 target 参数）。
- 渲染层级：`sortDepth()` 按 y 排序，并**节流到 ~0.12s** 真正执行（`update` 里消费 dirty 标记）——
  每次重排要动 2N 个子节点索引，10 只助手高频落地时全量重排很吃 CPU；顺序没变还会直接 early-out。
- 助手翻转也走随机落点（`helperFlip`），助手悬停高度改挂在 `PLAY_AREA.y1` 上。

### B. 姿态反向修正（重要）
贴图是「瓶口朝下」的，所以对调：
- `ok`（瓶口朝上）→ **angle 180** + `dy = bottleH*0.32`（翻正后原本最低点变瓶底，整体上抬）
- `crit`（瓶口朝下/扣盖）→ **angle 0**，无偏移
- `fail`（平放）→ **±93°** 随机左右
新建的瓶子初始就摆成 180°（瓶口朝上），`applyRest` 保证同排瓶底对齐。

### C. 音效（`Res.playThrottled` / `playThrottledRand`）
- 点击：`BottleField.flip()` 里按 'tap' key 节流 38ms 随机播 `click`/`click2`。
- 落地：`Bottle.land()` 里按 outcome 分：`ok→hit` / `crit→win` / `fail→pop1`，各自 key 节流（crit 90ms、其余 55ms）。
  **只有玩家亲手翻的才响**（`silent` 参数拦掉助手与冲击波），否则 10 只助手会响成一片。

### D. 性能优化（本轮重点，实测 fps 提升 2.5 倍）
1. **瓶盖全面对象池化**（`CapMachine` 重写）：开局预建 `POOL.chip = 72` 个节点，
   运行时只切 `active` + 改坐标/染色，**不用 tween、不用 scheduleOnce、不 new/destroy**；池满时多出来的瓶盖直接入账（不吞资源）。
2. **瓶盖统一单贴图** `bottle/capchip_0` + `Sprite.color` 染色区分品阶（7 张 capchip 贴图实测都是带色的，染色会发闷，
   但为了合批统一成一张最划算）。实测 25 颗 → 138 draw calls、64 颗 → 144，**瓶盖基本不增加 draw call**。
3. **特效层对象池化 + 分层**（`FxLayer` 重写）：建 `fxSprites` / `fxLabels` 两个子容器（精灵在下、文字在上），
   同层相邻节点才可能合批；飘字/爆散/星光/冲击波/闪屏全部池化 + 在 `update` 里手算位置缩放旋转透明度 → **零 tween、零 GC**。
4. **去掉每帧无谓写入**：HUD 的 money/inc/caps/pending/status 全部加字符串缓存，只有真的变了才写 `Label.string`
   （原实现每帧写 5 次 → 每帧重建文字网格）；`CapMachine` 的锁定态改色、`+N` 文本同样只在变化时写。
5. 爆散粒子数减半（crit 12→7、ok 5→3）；`sortDepth` 节流。

**压测对比**（10 只助手 + 100% 扣盖 + 手动灌满瓶盖池，headless 软件渲染无 GPU）：

| 阶段 | 优化前 fps | 优化后 fps |
|---|---|---|
| BASE(25 颗) | 22.3 | **55.2** |
| FLOOD1(64 颗) | 23.0 | **59.2** |
| FLOOD2(58 颗) | 21.0 | **42.9** |
| DRAIN(51 颗) | 25.6 | **52.6** |
| IDLE(45 颗) | 32.1 | **58.8** |

draw calls 稳定在 138~182 之间，与瓶盖数量基本无关（合批生效）。

**验收**（`_test6.txt`）：24 只瓶子位置全部落在 `PLAY_AREA` 内且彼此错开（如 `-3,193 / -13,-93 / 100,143 / 191,156 …`），
点击后位置改变、朝向分布为 180/0/±93 混合；`sfxKeys=tap,land_fail,land_crit,land_ok` 四种音效都被触发。
